# Context source selection (unreleased P5)

Context packages such as web/admin are optional. Core still provides Laravel view contexts, routing integration and shared client metadata. Host backend routes, view-context registration and security policies remain application concerns.

Use `.env` keys `SAOLA_CONTEXT_MODE=auto`, `SAOLA_WEB_MODE=standalone` (flat local views), `SAOLA_WEB_MODE=theme` with `SAOLA_WEB_THEME=default` (local themes), or `SAOLA_ADMIN_MODE=package` (installed context source). Any context is supported; use uppercase and replace hyphens with underscores in the env key. `published` retains explicit legacy compiler mappings.

The provider merges environment-backed `saola-contexts` configuration at registration. It is serializable with `config:cache`; runtime does not call `env()`. Per-context mode wins over the global mode. With `auto`, runtime follows builder metadata in `public/static/saola/contexts.json`; explicit choices must match that metadata. For nonstandard defaults, builder JSON config remains available. Full build-side precedence and setup are in the builder's [CONTEXT_PACKAGES guide](../../builder/docs/CONTEXT_PACKAGES.md).

`ContextSource::definition($context)` resolves source mode/theme/namespace, `isLocal($context)` identifies local source, and `apply($context)` sets the context base to the namespace in the build metadata and shares `saola.context.{context}`. `ThemeService::apply()` invokes it at each request. For example, `web.themes.paper.views` gives layout/module/component paths under that base. Older metadata without a namespace falls back to the context name. Explicit-mapping hosts register their base directly with `ViewContextManager::registerContext`. This selection does not delete cached installed-theme choices and does not apply them to local builds. `BundleManifest` excludes installed-theme bundles for local contexts and resolves the local CSS entry from the build mapping. Other installed runtime extension bundles remain supported.

After a mode/local-theme change: compile the context, rebuild Vite (restart the dev server during development), clear or regenerate Laravel config cache, then restart long-lived workers. An explicit mode/theme that differs from the build fails with a rebuild message; core does not hydrate a different layout from the one compiled. Keep metadata deployed together with its JS, CSS and Blade output.

Services are exposed on the client through the existing Application bundle/container, not new PHP App methods. This feature introduces no web/admin-specific service into a standalone context. Project services belong in `{context}/app`, presentation in `views` or `themes/{name}/views`, and public type augmentation should be imported by bootstrap or the optional local manifest `types` entry.
